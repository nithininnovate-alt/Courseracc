---
name: Orval codegen conventions (api-client-react)
description: Non-obvious naming/shape rules for the generated React Query client, to avoid wrong imports.
---

The portal's API client (`lib/api-client-react/src/generated/`) is generated by orval from `openapi.yaml`.

- **Request-body type names follow the OpenAPI schema `$ref`, not the operationId.** If a path's requestBody references `CertificateInput`/`CourierRequestInput`/`CourierUpdate`, the generated/exported type is exactly that name. There is NO `IssueCertificateBody` / `RequestCourierBody`. When passing `.mutate({ data })`, `data` matches that schema interface.
- **Query hooks are `export function useListX`; mutation hooks are `export const useXxx`.** So grepping `export const useList...` finds nothing — use `export function` for queries.
- Entity/schema interfaces live in `api.schemas.ts` and are re-exported from `@workspace/api-client-react` (import `type Certificate` etc. from the package root).
- Mutation call shape mirrors existing pages: create = `mutate({ data })`, update = `mutate({ id, data })`, with `{ onSuccess, onError }`; `.isPending` for loading.

**Why:** Guessing `<operationId>Body` names and `export const` for list hooks both fail and waste grep cycles.
**How to apply:** Before wiring a new generated hook, grep the actual export in `generated/api.ts` (queries: `export function`) and confirm the body type name from the schema `$ref` in `openapi.yaml`.
